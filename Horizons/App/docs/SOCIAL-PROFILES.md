# Social profiles

Profile is now the stats/social dashboard. The pencil opens the accepted editor (name, optional birth date, goal, clothes/hair/colors/etc.); Save returns to the dashboard, Back discards unsaved editor state. Native artwork and avatar registration remain unchanged. No new images were generated.

Public pages show display name, avatar, month/year joined, total XP, current/best streak, mastered vocabulary, completed lessons, learning days, and social counts/lists. Public data explicitly omits raw profile IDs, keys, birthdays, tokens and private attempts. Authenticated users can open competitor names/avatars from Rank or suggestion/search/connection cards. The route is #person/<opaque public ID>; it still requires a normal learner session.

Following is directed. A friend exists only while both active human follow edges exist. Unfollowing removes the mutual relationship. Bots use stable bot-0 through bot-19 personas across weeks and lobbies; they may be followed but never follow back or become mutual friends. Simulated public stats are separate from real learner records and cannot award XP or badges. No bot label is added to the interface, per the user's existing presentation instruction.

Suggestions prioritize activated human accounts, incoming followers first, excluding the viewer and already-followed accounts. Existing active Rank participants with legacy example keys are also discoverable; unrelated QA records are excluded. Bots fill remaining suggestion slots. Search is bounded to12 results, case/accent insensitive, with a two-character minimum. Individual keys remain private and are never search terms or invite payloads.

Follow state is stored in private HzThrottle records under social-out:<owner> and social-in:<public target>; IDs use server hashing. The outgoing row is authoritative and incoming mirrors are checked against it. Writes are idempotent. If a mirror write fails, retrying the requested follow state repairs it. Follow limit200. Unknown targets and self-follow are rejected. No new CMS permissions/collections are needed.

Find friends uses name search. Invite friends opens native sharing when supported, otherwise copies a URL or exposes a selectable copy field. The URL contains only the inviter's public ID. It grants no account/book access, awards nothing, and never follows automatically. A pending inviter survives login in session storage, then opens the inviter's public profile for an explicit follow choice. Sharing itself remains under the user's control.

Friend challenges: mutual human friends can send a private, seven-day, eight-question A1 vocabulary round. Random seed and full question snapshot are saved once on the server; the alphabet is excluded. Each participant has one immutable, server-graded result, stored separately to avoid concurrent overwrites. Own score is visible immediately; opponent score appears after both finish. Ties remain draws. Invitations may be declined; unauthorized users, expired access, nonfriends and bots cannot play. Maximum ten new invitations per sender/day and200 history entries. Both learners need active A1 access. Private challenge indexes/results use HzThrottle scopes, no new collections. No XP/mastery/streak/rank awards are attached to these casual challenges. No external messages sent. Challenges are available on own profile and sending on a mutual friend's profile. Results can be revisited from Challenges.
